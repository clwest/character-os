## §5 Proposed Slice 281.1 — smallest exact backend-only slice

**Implementation acceptance target.**

> Given a completed Composition attached to an Episode, a
> workspace-member operator can call
> `GET /api/compositions/<id>/suggested-memories/` and receive a
> JSON payload of ≤ N model-generated memory candidates suitable
> for the SPA's eventual "few ideas from what just happened"
> surface (Slice 281.2). No SPA changes. No production behavior
> changes to any existing endpoint or view.

The endpoint is functionally silent to today's operators — the
current SPA never calls it. Slice 281.2 will wire the curator
cards into `NarrativeMemoryPromotePanel` to consume it.

### 5.4 Remaining implementation assumptions (not yet proven)

1. **Cache TTL: 600s vs 1800s.** v1 reference uses `_CACHE_TTL_SECONDS = 600` (10 min).
   Handoff §3.Slice 281.1 says "Redis-cached (30-min TTL)".
   Handoff §3.Slice 281.2 later says "staleTime = 30min matching
   server cache" — implying the intent IS 30-min. Slice 281.1
   should pick one; the handoff internal wording says 30 min so
   `_CACHE_TTL_SECONDS = 1800` for the curator service.
   **Flag for ChatGPT arbitration** — if the 10-min pattern is
   preferred for consistency with the v1 story-direction
   service, this is a one-constant change.

2. **`memories` endpoint arity ("n").** Q280.9 asked for
   3-5 candidates. Handoff §3.Slice 281.1 default is `n=3`.
   Reference service clamps `[1, 5]`. **Recommendation:**
   inherit the reference clamp; default 3; treat 5 as the ceiling.
   Any `n` outside that clamps silently, matching reference
   behavior.

3. **Empty-realized-dialogue behavior.** Handoff says "Empty-
   substrate short-circuit — returns `{candidates: []}` if the
   composition has no realized dialogue." The current
   `synthesized_brief` column can be empty on FAILED /
   RUNNING / DRAFT compositions. **Recommendation:** treat
   `not composition.synthesized_brief.strip()` OR `composition
   .status != CompositionStatus.COMPLETED` as short-circuit
   conditions; return `{candidates: [], substrate_summary: {...},
   ...}` with no LLM call, same 200 status.

4. **Permission behavior for non-COMPLETED compositions.** Should
   a workspace-member calling on a DRAFT / RUNNING / FAILED
   composition get 200-with-empty-candidates or a 400? The
   handoff is silent. **Recommendation:** 200-with-empty
   matches the v1 empty-Universe short-circuit spirit and
   avoids leaking status information at the operator layer.
   The SPA (Slice 281.2) will not render the panel in those
   states anyway.

5. **Composition-scoped cache invalidation.** v1 keys by
   Universe id + latest_episode_at + latest_memory_at. Curator
   is composition-scoped; new memories on the SAME composition
   are the primary invalidation signal. **Recommendation:**
   key by `composition_id | latest_memory_at_for_composition | n`
   — where `latest_memory_at_for_composition` = the max
   `created_at` across `NarrativeMemory` rows with
   `source_composition_id == composition.id`. This means: a new
   `[Remember this]` on the same composition (either via the
   Slice 281.2 curator cards or the existing textarea) will
   naturally rotate the cache key on the next fetch.

6. **Vocabulary-leak invariant test scope.** Handoff §3 asks for
   "vocabulary-leak invariant on operator-facing error detail
   (banned-word list)". Slice 281.1 backend surfaces exactly ONE
   operator-facing string (the 502 detail). The candidate
   `body` and `narrative_gravity_note` fields ARE model output
   and MUST NOT be censored server-side; the SPA renders them
   raw. The vocabulary-leak invariant belongs primarily on the
   SPA in Slice 281.2. Slice 281.1's version checks only the
   backend-owned error string.

### 5.8 Risks / unknowns for Chris + ChatGPT decision gate

* **Cost budget.** Handoff §11.3 estimates ~$0.02/call cached
  30 min. If the SPA (Slice 281.2) polls or refetches on focus,
  cost balloons. Slice 281.1 cache-keying + Slice 281.2's
  `refetchOnWindowFocus=false` (per handoff) together bound
  this. Acceptable per handoff §7 acceptance criterion 5
  ("Cost per composition detail page load ≤ $0.03").
* **Model output variance.** Q280.9 ran with n=1 (§7.3
  deferred). If refreshed candidates vary drastically, operator
  trust suffers. Not a Slice 281.1 blocker — Slice 281.3
  dogfood will surface if variance is a real problem.
* **Composition-scoped invalidation over-eagerness.** Keying on
  `latest_memory_at_for_composition` means the cache rotates
  after every `[Remember this]` on the same composition. That
  matches operator expectation ("I promoted one, show me new
  ones next time") but does cost an extra LLM call per
  promotion cycle. Handoff acceptance criteria don't specify
  otherwise; matches operator-mental-model.
* **Prompt drift risk.** The Q280.9 probe's system prompt names
  memory kinds (event / action / promise / dialogue_callback /
  world_detail) as JSON output fields. Those kind strings must
  match `NarrativeMemory.KIND` choices exactly so Slice 281.2's
  `[Remember this]` mutation can pass `kind` through to
  `promote_from_composition` unchanged. **Recommendation:**
  Slice 281.1 imports `NarrativeMemoryKind` from the model to
  keep the prompt's kind vocabulary in sync with the model
  choices; a test asserts the prompt string contains every kind
  from the enum.

## §L2 Service shape

```python
def suggest_memories_from_composition(
    composition,
    *,
    n: int = 3,       # clamped [1, 5]; out-of-range → 3
    use_cache: bool = True,
) -> dict:
    """
    Returns:
      {
        "candidates": [
          {"body": str, "kind": str, "witnesses": list[str],
           "narrative_gravity_note": str}, ...
        ],
        "substrate_summary": {
          "prior_episodes_used": int,
          "existing_memories_used": int,
          "cast_count": int,
          "dialogue_chars": int,
        },
        "generated_at": ISO-8601 UTC str,
        "model": str,
        "cache": {"hit": bool, "ttl_seconds": int},
        "tokens_input": int,   # omitted on cache hit
        "tokens_output": int,  # omitted on cache hit
      }

    Raises SuggestMemoriesUpstreamError on provider error /
    unparseable response.
    """
```

Read-only. Never creates, edits, archives, supersedes, or
otherwise mutates any ``NarrativeMemory`` row.

## §L3 Endpoint shape

```
GET /api/compositions/<id>/suggested-memories/?n=3&refresh=false
```

* 200 on success (candidates list, possibly empty).
* 200 with ``candidates=[]`` on non-completed / empty-brief /
  no-episode compositions (no provider call).
* 404 on non-member / non-existent (queryset scoping).
* 502 on provider failure with the operator-facing envelope
  ``{"error": "suggestion_provider_unavailable", "detail":
  "Couldn't generate suggestions right now. Try again shortly."}``.
