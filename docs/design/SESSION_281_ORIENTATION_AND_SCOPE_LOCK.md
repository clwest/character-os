## §5 Proposed Slice 281.1 — smallest exact backend-only slice

**Implementation acceptance target.**

> Given a completed Composition attached to an Episode, a
> workspace-member operator can call
> `GET /api/compositions/<id>/suggested-memories/` and receive a
> JSON payload of ≤ N model-generated memory candidates suitable
> for the SPA's eventual "few ideas from what just happened"
> surface (Slice 281.2). No SPA changes. No production behavior
> changes to any existing endpoint or view.

The endpoint is functionally silent to today's operators — the
current SPA never calls it. Slice 281.2 will wire the curator
cards into `NarrativeMemoryPromotePanel` to consume it.

### 5.4 Remaining implementation assumptions (not yet proven)

1. **Cache TTL: 600s vs 1800s.** v1 reference uses `_CACHE_TTL_SECONDS = 600` (10 min).
   Handoff §3.Slice 281.1 says "Redis-cached (30-min TTL)".
   Handoff §3.Slice 281.2 later says "staleTime = 30min matching
   server cache" — implying the intent IS 30-min. Slice 281.1
   should pick one; the handoff internal wording says 30 min so
   `_CACHE_TTL_SECONDS = 1800` for the curator service.
   **Flag for ChatGPT arbitration** — if the 10-min pattern is
   preferred for consistency with the v1 story-direction
   service, this is a one-constant change.

2. **`memories` endpoint arity ("n").** Q280.9 asked for
   3-5 candidates. Handoff §3.Slice 281.1 default is `n=3`.
   Reference service clamps `[1, 5]`. **Recommendation:**
   inherit the reference clamp; default 3; treat 5 as the ceiling.
   Any `n` outside that clamps silently, matching reference
   behavior.

3. **Empty-realized-dialogue behavior.** Handoff says "Empty-
   substrate short-circuit — returns `{candidates: []}` if the
   composition has no realized dialogue." The current
   `synthesized_brief` column can be empty on FAILED /
   RUNNING / DRAFT compositions. **Recommendation:** treat
   `not composition.synthesized_brief.strip()` OR `composition
   .status != CompositionStatus.COMPLETED` as short-circuit
   conditions; return `{candidates: [], substrate_summary: {...},
   ...}` with no LLM call, same 200 status.

4. **Permission behavior for non-COMPLETED compositions.** Should
   a workspace-member calling on a DRAFT / RUNNING / FAILED
   composition get 200-with-empty-candidates or a 400? The
   handoff is silent. **Recommendation:** 200-with-empty
   matches the v1 empty-Universe short-circuit spirit and
   avoids leaking status information at the operator layer.
   The SPA (Slice 281.2) will not render the panel in those
   states anyway.

5. **Composition-scoped cache invalidation.** v1 keys by
   Universe id + latest_episode_at + latest_memory_at. Curator
   is composition-scoped; new memories on the SAME composition
   are the primary invalidation signal. **Recommendation:**
   key by `composition_id | latest_memory_at_for_composition | n`
   — where `latest_memory_at_for_composition` = the max
   `created_at` across `NarrativeMemory` rows with
   `source_composition_id == composition.id`. This means: a new
   `[Remember this]` on the same composition (either via the
   Slice 281.2 curator cards or the existing textarea) will
   naturally rotate the cache key on the next fetch.

6. **Vocabulary-leak invariant test scope.** Handoff §3 asks for
   "vocabulary-leak invariant on operator-facing error detail
   (banned-word list)". Slice 281.1 backend surfaces exactly ONE
   operator-facing string (the 502 detail). The candidate
   `body` and `narrative_gravity_note` fields ARE model output
   and MUST NOT be censored server-side; the SPA renders them
   raw. The vocabulary-leak invariant belongs primarily on the
   SPA in Slice 281.2. Slice 281.1's version checks only the
   backend-owned error string.

### 5.8 Risks / unknowns for Chris + ChatGPT decision gate

* **Cost budget.** Handoff §11.3 estimates ~$0.02/call cached
  30 min. If the SPA (Slice 281.2) polls or refetches on focus,
  cost balloons. Slice 281.1 cache-keying + Slice 281.2's
  `refetchOnWindowFocus=false` (per handoff) together bound
  this. Acceptable per handoff §7 acceptance criterion 5
  ("Cost per composition detail page load ≤ $0.03").
* **Model output variance.** Q280.9 ran with n=1 (§7.3
  deferred). If refreshed candidates vary drastically, operator
  trust suffers. Not a Slice 281.1 blocker — Slice 281.3
  dogfood will surface if variance is a real problem.
* **Composition-scoped invalidation over-eagerness.** Keying on
  `latest_memory_at_for_composition` means the cache rotates
  after every `[Remember this]` on the same composition. That
  matches operator expectation ("I promoted one, show me new
  ones next time") but does cost an extra LLM call per
  promotion cycle. Handoff acceptance criteria don't specify
  otherwise; matches operator-mental-model.
* **Prompt drift risk.** The Q280.9 probe's system prompt names
  memory kinds (event / action / promise / dialogue_callback /
  world_detail) as JSON output fields. Those kind strings must
  match `NarrativeMemory.KIND` choices exactly so Slice 281.2's
  `[Remember this]` mutation can pass `kind` through to
  `promote_from_composition` unchanged. **Recommendation:**
  Slice 281.1 imports `NarrativeMemoryKind` from the model to
  keep the prompt's kind vocabulary in sync with the model
  choices; a test asserts the prompt string contains every kind
  from the enum.

def suggest_memories_from_composition(
    composition,
    *,
    n: int = 3,       # clamped [1, 5]; out-of-range → 3
    use_cache: bool = True,

    """

      {
        "candidates": [
          {"body": str, "kind": str, "witnesses": list[str],
           "narrative_gravity_note": str}, ...

          "cast_count": int,

        },
        "generated_at": ISO-8601 UTC str,
        "model": str,
        "cache": {"hit": bool, "ttl_seconds": int},
        "tokens_input": int,   # omitted on cache hit
        "tokens_output": int,  # omitted on cache hit

    Raises SuggestMemoriesUpstreamError on provider error /
    unparseable response.
    """

## §M5 Card behavior

Local state machine per card: `pending → editing → pending`
(cancel/save) OR `pending → remembered` (successful mutation)
OR `pending → skipped` (dismiss, no persistence).

* **Remember this** (default): calls `promote.mutateAsync`
  with body + `witnessed_by: []`. On success, card collapses
  to a lightweight `✓ Remembered.` state and the existing
  recap query invalidates via `usePromoteMemories.onSuccess`
  (already wired since SESSION 264). No page reload.
* **Edit**: swaps the body paragraph for an inline `<textarea>`
  prefilled with the candidate body. Save uses the same
  persistence policy (body + `witnessed_by: []`, no hidden
  metadata). Cancel restores the original card.
* **Skip**: sets local status to `"skipped"`; the card returns
  `null` on the next render. No mutation. No telemetry.

### N5.2 Where the "talk about it" behavior most plausibly entered

**The interaction between the topic grammar and the
`dialogue_scene` primitive's built-in conversation frame.**
Specifically:

* The topic supplies an off-stage actor and a request but no
  on-stage character taking action.
* The `dialogue_scene` primitive is by-design a two-
  character conversation; it does not have an off-stage-
  event → on-stage-consequence shape in its narrative
  menu.
* The two present cast members (Ruby, Tyson) both carry
  Teammate `business_brief` fields that describe them as
  customer-service explainers.
* Result: the highest-probability reading of "a customer
  asks X" given the primitive's shape menu and the cast's
  business briefs is **"the two characters at the counter
  discuss how to handle this customer's ask."**

This is **not** best explained by "the model did it." The
model is faithfully composing across the following prompt
constraints:

* task: "here is the topic" (verbatim, no shaping hint)
* shape: "this is a conversation" (§4)
* cast business shape: "helps customers choose" (§1)
* narrative menu: 8 talk shapes, no event-arrival shape (§4)

Given that composition, "characters at the counter
discussing the ask" is the natural output. The failure is a
**topic ↔ primitive impedance mismatch** — the topic
described an event, the primitive is a conversation format,
and no prompt layer bridges the two by putting the customer
on stage or dramatizing the ask arriving.

### N5.3 Confidence: HIGH that this is systemic-conditional

The failure is not ordinary variance. It is:

* **Systemic** when a topic supplies an off-stage actor + a
  request/ask/event without an on-stage character verb, AND
* **Conditional** on the operator topic grammar — the same
  primitive produced a strong scene when the topic supplied
  an on-stage character verb (`772e9012`).

A topic like "Ruby handles a difficult customer asking for a
competition cake, only for Tyson to disagree about how
neighborhood-branded to make it" would very likely produce
an event-shaped scene from the same primitive. This is a
falsifiable prediction (see §N9 candidate probes).

## §N6 Q281.3-B — Does retrieved memory create pressure for explicit use?

**Answer:** yes, subtly. Two mechanisms, in order of
strength.

### N6.1 Supply-side pressure (dominant)

`retrieve_universe_memory` runs with `top_k=1` per
`dialogue_synthesis.py:1586`. If ONE memory row is returned,
the whole `NARRATIVE MEMORY` block appears in the prompt. If
zero rows are returned, the block is omitted entirely
(§`_build_factual_basis_section` line 603 gate: `if
memory_rows:`).

**Semantic implication for the LLM.** Once the block appears,
the LLM correctly infers that this specific memory was
selected as topically relevant to the current scene. The
retrieval predicate uses the operator topic as the query
vector (line 1586: `retrieve_universe_memory(workspace,
canon_universe, cast, topic, top_k=1)`). Semantic overlap
between the topic ("celebration cake for an event tied to
the neighborhood baking competition") and the mascot memory
("welcoming mascot for the neighborhood") is real — both
share the "neighborhood" anchor. So the memory is
legitimately topical.

From the LLM's perspective the composition is:
* "Here is the scene topic."
* "Here is a memory that was selected as relevant to this
  scene."
* "Use them as historical context or callback material
  where natural."

That structural composition creates supply-side pressure:
**the memory's mere presence in the prompt says 'this is
relevant to this scene.'** In the failing specimen the model
did the natural thing — worked the mascot into the
dialogue.

### N6.2 Wording pressure (secondary, mild)

`_build_factual_basis_section` lines 620-623:

> "These are operator-promoted story memories. **Use them as
> historical context or callback material where natural.**
> Do not recite them verbatim; treat them as background the
> cast already knows happened."

Comparison with the canon SHARED WORLD KNOWLEDGE block
header on line 593:

> "--- SHARED WORLD KNOWLEDGE (any character may cite) ---"

Canon is framed permissively (**may** cite). Memory is
framed with an imperative verb (**Use them**) softened by a
condition (**where natural**). The permissive escape hatch
exists, but the default reading is directive.

This is a mild asymmetry vs canon and could plausibly
combine with the supply-side pressure above.

### N6.3 Was the mascot callback natural or mechanically encouraged?

**Best-supported answer: mechanically encouraged.** Three
independent observations:

1. **Topic-driven retrieval seeding.** The retrieval query
   was the topic itself. The memory that came back was
   selected specifically because it overlapped the topic.
   Once selected, its presence signals relevance to the
   model.
2. **Turn placement is symptomatic.** The mascot callback
   lands at turns 6-7 out of 10 — after the operational
   discussion has run out of primary material. It reads
   like fitting the memory in rather than the memory
   driving the arc. Compare `772e9012` where the mascot
   idea IS the second beat of the scene (Ruby proposes
   routine → Tyson raises mascot complication → resolution),
   originating naturally from the topic itself and driving
   the arc.
3. **Ruby's line preserves the memory verbatim in
   spirit.** "I still think the neighborhood deserves a
   welcoming little face" is a near-paraphrase of the
   remembered body ("Ruby still wants Fox & Flour to have a
   welcoming mascot for the neighborhood"). The framing
   instruction "Do not recite them verbatim; treat them as
   background the cast already knows happened" was
   partially honored — Ruby doesn't quote the memory — but
   the wording maps 1:1.

Ruling out alternatives:
* **Ranking?** Not the cause — the memory is the ONLY
  eligible active + embedded row in Fox & Flour that
  overlaps the topic; `top_k=1` returned exactly what it
  was designed to return.
* **Verifier / coverage pressure?** Not the cause — K6.4
  verifier scores factual claims against allowed
  vocabulary. The mascot line "welcoming little face" isn't
  a factual claim about a K2 chunk. `verification_status =
  verified` with 0 warnings; the verifier neither required
  nor rewarded the callback.
* **Model creativity variance?** Only partially. The model
  has to place the memory somewhere if it's in the prompt;
  the placement was reasonable but the necessity was
  supplied by the prompt, not by the scene's structural
  need.

## §O9 Q281.3-α verdict

**Topic grammar alone materially changed story execution.**

Same substrate. Same primitive. Same 90s target. Same model.
Same corrective loop. Same production code. **Different topic
grammar → substantially different scene shape.**

Specifically:

* **Event vs discussion.** CONTROL described a received
  request past-tense; TREATMENT described an event unfolding
  in the moment (call taken, ethical problem realized,
  decision made). TREATMENT put an event on-stage; CONTROL
  did not.
* **Procedural turn count.** CONTROL ~4/11 procedural,
  TREATMENT ~0-1/11 procedural. TREATMENT is dominated by
  event/reaction/consequence beats.
* **Q→A→advice collapse.** CONTROL exhibited the pattern
  clearly; TREATMENT did not — both characters aligned on
  the same side almost immediately and the scene built
  toward a decision under pressure.
* **State change.** CONTROL ended with characters still
  waiting for information; TREATMENT ended with Ruby about
  to make a specific counter-offer call.

**This falsifies "ordinary variance" as an explanation for
the `565cd8c8` finding.** The failure mechanism §N5 proposed
(topic-grammar × primitive-shape impedance) is corroborated:
supplying an on-stage character verb + explicit complication
in the topic pulls the same primitive into event-shaped
territory without any production change.

## §O10 Effect on Q281.3-B hypothesis (memory-use pressure)

TREATMENT retrieved a **different memory** than CONTROL from
the same pool, because the retrieval query vector is the
topic itself. This means the paired probe **cannot cleanly
isolate memory-presence pressure**: the treatment arm didn't
have the mascot memory in-prompt to callback in the first
place.

However, the paired probe does reveal a subtler pattern:

* CONTROL retrieved a memory (mascot) that overlapped the
  topic lexically ("neighborhood" anchor) but not
  structurally — the scene didn't need a mascot; the mascot
  fit in mid-scene as filler-riff (§O8 row 8c).
* TREATMENT retrieved a memory (cooperation) that overlapped
  the topic structurally — a scene about Ruby taking a call
  and needing to check with Tyson literally reflects
  "neither one leaves until the other says they have what
  they need." Ruby's turn 4 line "I told them I'd check
  before promising anything" is what a cast that lives by
  the cooperation memory would do.

**Preliminary reading:** when retrieval alignment is
structural (memory shape aligns with scene shape), the
callback feels natural. When retrieval alignment is only
lexical (memory topic overlaps scene topic without
structural need), the callback feels inserted.

**Q281.3-β is still worth running** to cleanly isolate
memory-presence pressure. Specifically, a probe design that
fires the SAME topic (either CONTROL or TREATMENT) TWICE —
once with `retrieve_universe_memory` result intact, once
with `memory_rows=[]` forced (probe-local override, no
production change) — would isolate the supply-side pressure
independent of retrieval alignment.

**Q281.3-γ (memory-framing wording swap) drops in
priority.** The observed variation here suggests that
retrieval choice is a stronger channel than block wording
for shaping callback behavior. Q281.3-γ still valid but
lower-value than Q281.3-β.

## §O11 What is PROVEN (post-probe)

* Topic grammar (off-stage-request vs on-stage-character-
  action-plus-complication) materially changes
  `dialogue_scene` output shape at fixed everything else.
  n=1 paired specimen; falsifiable at ~$0.20-0.30 per
  additional paired run if Chris + ChatGPT want higher n.
* The `565cd8c8` failure is NOT ordinary model variance —
  it is a reproducible consequence of a systemic-conditional
  interaction between topic grammar and the
  `dialogue_scene` primitive's shape menu (§N5.2).
* Retrieval query is topic-embedding-driven. Different
  topics on the same substrate pull different top-1
  memories. TREATMENT's different memory retrieved reveals
  this cleanly.
* Curator conclusions from §N7 are unaffected. The paired
  probe did not test the curator on either arm. TREATMENT
  would presumably produce more event-shaped curator
  candidates because the source material is event-shaped;
  this is a further probe if Chris + ChatGPT want to run
  it.
* Zero production code changes. Zero DB mutations. Both
  SESSION 280 Fox & Flour memories still unmodified. Mascot
  memory `73acdfc0` still `status=remembered`, unarchived,
  body verbatim.

## §O12 What remains AMBIGUOUS (post-probe)

* **Effect strength on repeated runs.** n=1 per arm. Whether
  the treatment reliably produces event-shape across, say,

  discussion) is unknown. TREATMENT's grammar carries much

* **Effect across Universes.** Only Fox & Flour tested. Same
  pattern may or may not hold for Patch/Rivet (Patch's

* **Memory-presence pressure isolated.** See §O10 —
  Q281.3-β would clean this up.
* **Whether v1 story-direction generator can produce
  TREATMENT-shaped topics.** Not tested. The v1 suggestion

## §P1 The mistake

Q281.3-α authorized budget: **~$0.04**
Q281.3-α actual spend:      **~$0.26** (~6.5×)

Origin of the error (§N10.a): I derived the ~$0.04 estimate
from Q280.9's curator per-call cost (~$0.02 for ~1600
tokens, single call, minimal prompt). I did NOT re-estimate
for a full `dialogue_scene` synthesis, which has a much
larger prompt (retrieval + K2 + WC + FB + memory + task
blocks ≈ 8500 tokens input) AND commonly requires two
attempts (first-pass + corrective).

## §P2 The rule for future probe cost estimates

**Never estimate a `dialogue_scene` synthesis probe by
extrapolating from curator-call cost.** They differ by
~5-10× per call and `dialogue_scene` frequently fires twice
per composition.

Reference numbers from SESSION 280 §11.3 + Slice 281.1 real-
provider verification + Q281.3-α:

| primitive / call type                            | tokens_in / call | tokens_out / call | typical cost / call | calls / probe   |
|--------------------------------------------------|------------------|-------------------|---------------------|-----------------|
| `next_episode_suggestions` (v1 story-direction)  | ~600-900         | ~100-200          | ~$0.005-$0.02       | 1               |
| Q280.9 / Slice 281.1 curator (composition-scoped)| ~1300-1600       | ~150-300          | ~$0.02              | 1               |
| `dialogue_scene` synthesis (v1 shipping path)    | ~7000-9500       | ~1200-1800        | **~$0.05-$0.10**    | **1-2** per composition |

Rule of thumb: for `dialogue_scene` synthesis probes,
estimate at **~$0.10-$0.20 per composition** (single-arm)
and **~$0.20-$0.40 per paired composition probe** (two
arms). Then add ~20-40% headroom for the correction retry
firing.

**Curator per-call cost is NOT a proxy for full-scene
synthesis cost.** They live in different order-of-magnitude
brackets.

## §R8 What substrate characteristics plausibly explain the difference?

Distinguishing evidence from hypothesis:

**Evidence (directly observable in substrate):**

1. **Episode-title grammar** — Patch's Workshop titles are

   finds Y", "Patch tells Rivet Z"). Fox & Flour Episode

   titles are longer + more action-shaped.
2. **Memory volume** — 14 vs 4 (3.5×). More memory content
   in the prompt means more named continuity threads for
   the generator to riff on.
3. **Memory body grammar** — all 14 Patch memories are
   `kind=event` with character-attributed narrative bodies
   ("Patch built X"; "Rivet has come to believe Y"; "The
   workshop agent began Z"). Fox & Flour's 4 memories are
   also event/promise-shaped but shorter and less
   character-attributed.
4. **Cast business-brief framing** — Patch's briefs describe
   experimental behavior ("Patch builds strange things to
   find out whether they work"; "Rivet helps him build,
   test, measure"). Fox & Flour's briefs describe customer-
   service roles ("Helps customers choose what fits the
   occasion without overcomplicating it").
5. **Universe.brief presence** — Fox & Flour has a paragraph
   framing the bakery as a "warm neighborhood gathering
   place." Patch's Workshop's is empty. Counterintuitively,
   the empty brief may HELP because it removes a soft
   customer-service framing pressure.

**Hypothesis (not directly proven by this probe):**

* The dominant driver is likely the combination of memory
  body grammar (character-attributed events) + episode-
  title grammar (cast-verb) + business-brief framing
  (experimental vs service). These three combine to prime
  the generator toward cast-verb suggestions.
* Memory volume alone is probably not sufficient — 14
  memories all in the "customer wanted this" shape wouldn't
  produce Patch's distribution. Memory SHAPE matters more
  than count.
* Universe.brief absence is probably a modest positive but
  unproven — an ablation probe (F&F with brief cleared)
  would isolate.

None of these hypotheses are actionable without further
probing. Recorded for durability.

## §R9 Effect on Hβ (v1 topic-grammar contract)

**Hβ significantly weakened as a global fix.**

The Q281.3-ε reading was "the generator has no dramatizability
requirement, so it produces mixed output." The Q281.3-ζ
reading is more precise: **the generator's output quality
tracks the input substrate's shape.** Given a rich, character-
attributed, event-shaped substrate (Patch's Workshop), it
produces near-uniformly strong-shape suggestions with 100%
complication. Given a thin, service-framed substrate (Fox &
Flour), it produces a mixed distribution including occasional
worst-case topics.

Two implications:

* **Hβ-strict** (v1 prompt requires A+B+C on every
  suggestion) would probably not measurably change Patch's
  Workshop output (already 60% strict-strong, 100%
  complication). It would help Fox & Flour but might
  suppress the legitimate 27% mixed-shape variety.
* **Hβ-permissive** (soft preference for dramatizable
  shape) same weak effect on rich substrates; helpful on
  thin substrates.

**A cleaner fix candidate emerges from Q281.3-ζ evidence:**

* **Hθ (new hypothesis, from Q281.3-ζ):** the failure
  signal is upstream of the generator. Fixing the generator
  prompt papers over a **substrate quality** issue. The
  correct product response may be to give operators a way
  to enrich thin substrates — either via curator (which
  Slice 281.2 already ships) or via first-Episode substrate
  guidance during Universe creation.
* **Hι (new hypothesis, from Q281.3-ζ):** the v1 generator
  prompt could take Universe-substrate quality into account
  and shift shape prescriptions based on substrate density
  ("if past events are rich and character-driven, prefer
  callback shapes; if past events are thin or service-
  shaped, prefer inventing on-stage complications from
  scratch"). More complex to implement, more targeted
  effect.

## §S8 Did rich continuity protect the scene?

**Evidence: yes, plausibly — but n=1 and multi-factor.**

1. **Topic verb tense.** "Box begins making a sound at

   happened offscreen.
2. **Cast business-brief framing** (experimental vs service).

   whether they work"; Rivet's brief: "reluctant accomplice
   … asking Why? usually won't stop him." These shape the
   default scene into experimentation-under-uncertainty, not
   customer-service intake. Turn 3's "That is not the same

   experimental voice.
3. **Retrieved memory shape.** The workshop-agent memory
   provides Patch with something he DOES remember to
   contrast against the box he DOESN'T. The memory
   structurally serves the topic's "partial memory admit"
   premise rather than fitting mid-scene as filler.
4. **Absence of business-service framing.** Fox & Flour's

   cast briefs ("helps customers choose what fits the

   service intake. Patch's Workshop lacks this. Empty

   methodical testing" role. His pressing turns (4, 6, 8)

structurally-aligned retrieved memory, not any single axis.

* Q281.3-ξ retrieved a structurally-aligned memory
  (workshop-agent notes) that supplied usable dramatic
  substrate for Patch's partial-memory arc.

**Evidence AGAINST (or complicating):**

* Q281.3-α TREATMENT succeeded on Fox & Flour's THIN
  substrate — proving substrate is not a HARD requirement
  for event-shape.
* Q281.3-ε: 53% of Fox & Flour's v1 suggestions are

  The generator produces good topics from thin substrate
  more often than not.
* Q281.3-ξ used only 1 retrieved memory out of Patch's
  Workshop's 14; the other 13 didn't contribute. Volume
  is not the axis.

**Refined interpretation:**

Rich substrate INCREASES the reliability of the generator +
primitive combination. Thin substrate has HIGHER VARIANCE —
it hits worst-case shapes more often (~7% weak-CONTROL on
F&F, 0% on Patch's Workshop) — but is not deterministically
bad. What matters most about substrate is SHAPE (character-
attributed event bodies + on-stage-action episode titles +
experimental cast briefs) more than COUNT.

The curator loop (Slice 281.1/281.2) is already the organic
mechanism for accumulating shape-correct substrate over time.
Every curator-noticed detail Chris promotes becomes a
character-attributed event memory that structurally aligns
with future scene retrieval.

  responsibility + leaks implementation vocabulary.

  ξ together produce the cleanest signal — same generator,

### OPTION D — Hι (generator adapts to substrate quality/density)
